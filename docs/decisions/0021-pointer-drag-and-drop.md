# ADR-0021: Pointer-based drag and drop
Status: accepted. The canvas is a sandboxed iframe, and HTML5 drag-and-drop does not cross that boundary reliably in real browsers (drops were ignored unless the pointer happened to be over an element, and tiles only worked by clicking). Dragging now uses pointer events (`features/editor/pointer-drag.ts`): a press that moves 5px starts a drag, a full-screen overlay keeps the iframe from swallowing events, and the editor asks the canvas (via a postMessage hit test) or the layers panel (`elementsFromPoint`) what is under the pointer. When the pointer is not over an element the canvas falls back to the nearest top-level element, or the page root for an empty page. Escape cancels, and the click that follows a drag is swallowed. Clicking a tile still inserts it.
