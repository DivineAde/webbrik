# ADR-0020: Real columns for users, sessions, workspaces and memberships
Status: accepted. These four tables now have one column per field (`email`, `password_hash`, `name`, `email_verified_at`, `avatar_url`, `last_login_at`, `created_at`, `updated_at`, `plan`, `role`, …) with proper types (TIMESTAMPTZ, BOOLEAN, JSONB only for genuinely free-form fields), unique indexes (e.g. lower-cased email) and foreign keys. Every other table keeps the generic id + JSON `data` layout from ADR-0016. The persistence interface still exchanges JSON strings, so the rest of the API is unchanged; `relational.ts` maps fields to columns per dialect. Migration `003_typed_columns` upgrades an existing database in place by creating the columns, copying values out of the old JSON blob and keeping the blob until the copy succeeds. Back up before the first start on an existing database. Trade-off: upgraded SQLite files leave the new columns nullable (SQLite cannot add NOT NULL in place); fresh databases get the full constraints.
